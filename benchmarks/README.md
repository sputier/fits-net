# Eleris.FitsNet benchmarks

Two [BenchmarkDotNet](https://benchmarkdotnet.org) projects. Always run them in **Release** and, for stable numbers, with nothing else
heavy running on the machine.

| Project | What it measures | Data |
|---|---|---|
| `Eleris.FitsNet.Benchmarks` | Images: reading, writing, cutouts, checksums, header parsing, tile compression (Rice, GZIP_1, GZIP_2, HCOMPRESS, PLIO, float quantization) on one core and on all cores | The three real raw frames in `data/vespera` (Vaonis Vespera Pro 2, 3536 x 3536, 12 bit in 16 bit) |
| `Eleris.FitsNet.Benchmarks.Tables` | Binary tables (10 000 to 2 million rows), variable-length arrays, ASCII tables, files with many extensions | Synthetic, generated by the benchmarks |

## Running

```powershell
# everything in a project (long: several minutes to an hour)
dotnet run -c Release --project benchmarks/Eleris.FitsNet.Benchmarks -- --filter "*"

# one class
dotnet run -c Release --project benchmarks/Eleris.FitsNet.Benchmarks -- --filter "*CompressionBenchmarks*"

# a quick, less accurate pass (a few seconds per benchmark) - good to check that nothing regressed
dotnet run -c Release --project benchmarks/Eleris.FitsNet.Benchmarks -- --filter "*ImageIoBenchmarks*" --job short

# what exists
dotnet run -c Release --project benchmarks/Eleris.FitsNet.Benchmarks -- --list flat
```

Results (Markdown, CSV, HTML) are written to `BenchmarkDotNet.Artifacts/` in the directory you run from.

## Reading the numbers

* `Mean` is a time per operation; the image is 25 MB, so 25 ms is 1 GB/s.
* `Allocated` is the managed memory allocated per operation. Pixel arrays are large-object-heap allocations, so `Gen2` appears for them.
* `Parallelism` is the `MaxDegreeOfParallelism` of the compression options: `1` is sequential, `-1` uses one tile per core at a time.
  Tiles are independent, so the speedup follows the number of cores until memory bandwidth is the limit; the output is byte-for-byte
  identical whatever the setting.
* Each compression class prints its **compression ratio** once at the beginning of the run (lines starting with `//`).

## What to compare

* `CompressionBenchmarks`: Rice is the best compromise for integer images, GZIP_2 beats GZIP_1 on 16-bit data, HCOMPRESS compresses
  noisy images well but is the slowest, NOCOMPRESS is the cost of the table machinery alone.
* `FloatCompressionBenchmarks`: the price of quantization and dithering against lossless `GZIP_2` (`Quantization = None`).
* `ImageIoBenchmarks`: `Cutout` shows that a region is read without loading the image; the checksum cases show the cost of
  `CHECKSUM`/`DATASUM`.

## Against cfitsio and astropy

`comparison/` holds the same operations written for cfitsio (through the `fitsio` package) and for astropy, the raw results, and the script that builds
the tables of `docs/comparison.md`. See that page for the method and the figures.
